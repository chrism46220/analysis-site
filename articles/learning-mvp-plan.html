Agent Learning — MVP Implementation Plan

Minimal viable learning stack. Prioritize capture over extraction. Target: one focused afternoon to implement.

Scope: What We Build

MVP Build: learning/ directory, post-task experience records, pre-task retrieval, index, wiki summary, error pattern capture

Defer Skip: playbook extraction, reflection engine, preference profile, config proposals, Talkie preference wiring

1. Directory & Seed Files

Create ~/.openclaw/workspace-plato/learning/ with seed files.

learning/
├── experiences/          # one JSON file per task
├── preferences.json      # seeded empty, populated later
├── error-patterns.json   # starts as []
├── learning-wiki.md      # human-readable summaries, indexed by wiki
└── index.json            # fast lookup table

Seed templates (copy-paste ready):

index.json

{
  "by_task_type": {},
  "by_task_hash": {},
  "by_tag": {},
  "experience_count": 0
}

error-patterns.json

[]

learning-wiki.md

# Learning Wiki

Auto-compiled summaries. Each entry is appended after task completion.
Searchable via `memory_search(corpus=wiki, query="...")`.

preferences.json

{
  "style": { "verbosity": "concise", "tone": "neutral", "format": "plain" },
  "routing": { "prefer_fast": false, "prefer_safe": true },
  "feedback_history": { "accepted": 0, "rejected": 0, "corrections": [] }
}

Estimated time: 5 minutes

2. Plato AGENTS.md — Post-Task Experience Write

Add a new section to Plato's AGENTS.md. After every task that completes (success or failure) and meets these criteria:

  • Nontrivial (not a simple Q&A)
  • Repeatable task type
  • Output involved execution or reasoning beyond a direct answer

Plato must explicitly include in its return-to-Talkie packet:

LEARNING: {
  "record": {
    "agent": "plato|manny|q",
    "task_type": "deploy|code_review|troubleshoot|data_gather|analyze",
    "input_summary": "short description",
    "context": {
      "routing": "flow string",
      "model": "model name",
      "duration_ms": number,
      "outcome": "success|failure|partial"
    },
    "patterns": {
      "key_commands": ["cmd1", "cmd2"],
      "key_decisions": ["decision1"],
      "error_signals": ["error text if any"]
    },
    "outcome_note": "summary for human",
    "tags": ["tag1", "tag2"]
  }
}

Then Plato routes to Q for verification (no exception — Q gate applies). If Q approves, write the file:

learning/experiences/YYYY-MM-DD-tasktype-uuid.json

And update learning/index.json:

// add to:
by_task_type[record.task_type].push(filepath)
by_task_hash[record.task_hash] = filepath
by_tag[tag].push(filepath)  (for each tag)
experience_count++

And append to learning/learning-wiki.md:

## YYYY-MM-DD
- **Task type** (exp-uuid, outcome)
  - Outcome note (1 line)
  - Key decisions: ...

Changes to AGENTS.md: Add a new section ## Learning Behavior at the end, with subsections for post-task write and pre-task retrieval.

Estimated time: 30 minutes (including routing + Q gate instructions)

3. Plato AGENTS.md — Pre-Task Retrieval

Before routing to manny or a specialist, Plato checks if there are relevant learnings:

## Learning Behavior — Pre-Task

### Before planning a task:
1. Read learning/index.json
2. If the task_type has entries in by_task_type, read the most recent 2 records
3. If any error-signal-related patterns exist in error-patterns.json for this context, fetch them
4. Prepend findings as:

RELEVANT_LEARNINGS:
  similar_tasks:
    - [outcome_note from recent experience]
  known_errors:
    - [error_signal: mitigation]

Graceful degradation rule: if learning/index.json doesn't exist or is empty, proceed normally (no crash).

Estimated time: 20 minutes (edit to AGENTS.md)

4. Error Pattern Capture on Failure

When a task fails, in addition to writing an experience record, Plato checks learning/error-patterns.json:

  • Does any error_signal from the task match an existing entry?
  • If yes: increment hit_count, update last_seen
  • If no: add new entry with placeholder mitigation (human fills later)

File access goes through manny. Plato sends the instruction; manny does the read/update.

Estimated time: 15 minutes (edit to AGENTS.md)

5. Wiki Registration

Register the learning wiki so it's searchable via memory_search(corpus=wiki).

Check if wiki registration is configured in openclaw.json. If not, add:

// In openclaw.json, under the plato agent entry:
"wiki": {
  "files": ["learning/learning-wiki.md"],
  "refresh_on_load": true
}

Or consult the compiled-wiki docs for the correct config format. If no per-agent wiki config exists, consider a shared wiki file in the plato workspace.

Estimated time: 10 minutes

6. Q Gate — Experience Verification

Q's existing Mandatory Gate rules already cover this. No config change needed — just ensure Plato's instructions say "route to Q before writing experience records."

Q checks:

  • Are all required fields present? (agent, task_type, context.outcome, created_at)
  • Is outcome_note non-empty and factual?
  • Does patterns.error_signals contain real error text (not "N/A" or empty)?
  • Is the task hash consistent with the input_summary?

Proposed Q gate verbiage to add to Q's AGENTS.md:

## Learning Record Verification

When verifying experience records:
- Confirm all required fields are present
- Check outcome_note is specific and factual
- Flag records where error_signals contains obviously fake or empty values
- Reject records missing created_at, context.outcome, or task_type

Estimated time: 10 minutes (edit to Q's AGENTS.md)

Measurable Success

After this MVP, you can:

  1. Run 3-4 real tasks (deploy, code review, troubleshoot)
  2. Check learning/experiences/ for records
  3. Search learning-wiki.md for summaries via memory_search(corpus=wiki)
  4. Verify error-patterns.json grows on failures
  5. Confirm pre-task retrieval picks up recent similar experiences on repeat tasks

Risks & Mitigations

RiskMitigation
Experience file explosionPrune after each file hits 50 records (manual). Set a 30-day retention.
Index out of syncRegeneration script (find experiences/ -name '*.json' | jq -s ... > index.json)
Latency from file I/OFlat JSON files under 50 records — negligible. Revisit at 100+.
Plato writes malformed JSONQ gate catches format issues before commit.
Wiki refresh staleAdd refresh_on_load: true or a periodic openclaw wiki refresh.
